## 🌟 What is Agent App Forge?

Agent App Forge is an open-source, agent-agnostic infrastructure layer that enables AI coding assistants (such as Google Antigravity, Claude Code, Cursor, and OpenCode) to autonomously investigate existing software, synthesize clean full-stack web applications with high-performance SQLite WAL storage, run verification loops, and repair detected defects within bounded limits.

Users can simply say:
- *"Recreate https://example.com"*
- *"Build a student management app with attendance and fee tracking."*

Forge automatically classifies the intent, extracts URLs or local paths, selects required tools, generates the application, and returns a verified result report.

## 🚀 Key Capabilities in v0.1.1

1. **Zero-Configuration Experience (Phase 15):**
   - Natural language intent classification: Automatically routes requests into greenfield generation, reference recreation, modification, or code inspection without requiring users to specify engines or MCP tool names.
   - Automatic URL & path extraction: Launches deep headless browser or local filesystem inspection directly from user prompts.

2. **Dedicated Domain Synthesis Engines (Phase 16):**
   - **Static & Documentation Content (`contentPageTemplate`):** Scaffolds clean informational portals with responsive typography, persistent SQLite storage, and zero fabricated task management forms.
   - **API Documentation & Service Explorers (`apiDocsTemplate`):** Synthesizes interactive API explorers featuring Swagger-like HTTP method badges (GET, POST, PUT, DELETE), expandable operation groups, live endpoint probing, and SQLite metrics telemetry.
   - **Student & Academic Directory (`studentManagementTemplate`):** Generates full-stack student portals with attendance tracking, fee status tracking, grade analytics, and automated SQLite WAL persistence.

3. **Dual-Track Parity Scoring & Verification (Phase 16):**
   - Rigorously decouples **Generated Application Quality** (server start, route responsiveness, WAL database integrity, cold reboot persistence) from **Reference Fidelity** (headings match, hyperlink preservation, control count parity, responsive viewports).
   - Strict enforcement: A pass in Application Quality **never** masks a failure in Reference Fidelity. Both tracks must pass for an overall passing score.
   - Anti-fabrication penalty (Rule 5): Penalizes synthesis of unobserved interactive controls on read-only reference pages.

4. **Brand-Neutral Generalization (Phase 17 & 17.1):**
   - Completely removed all hardcoded website keywords (`httpbin`, `todomvc`) from classification, engine routing, and comparator logic.
   - Structural API documentation detection using observable Swagger/OpenAPI elements (`Expand operation`, `Try it out`, `Execute`, `curl`, method badges).
   - Structural minimalist task app detection and dynamic evidence-based footer generation (preserves reference links only when supported by observed evidence or explicit user requests).

5. **Context-Optimized MCP Server:**
   - Exposes **9 compact core tools** by default (<6 KB schema, saving over 194,000 tokens per turn), with on-demand dynamic discovery across all 207 REA reverse-engineering analysis tools.

## 🔌 Connecting to Google Antigravity MCP

To connect the local Agent App Forge MCP server to Google Antigravity, add the server to your Antigravity MCP configuration.

### Configuration
```json
{
  "mcpServers": {
    "agent-app-forge": {
      "command": "node",
      "args": ["D:\\git hub\\agent-app-forge\\bin\\mcp.js"]
    }
  }
}
```
*(Replace `D:\\git hub\\agent-app-forge` with your actual repository path).*

### Verifying Connection
1. In your AI coding assistant, run `forge_capabilities` or ask the assistant: *"What tools does Agent App Forge provide?"*
2. The assistant will report the 9 core tools: `forge_capabilities`, `forge_inspect_reference`, `forge_create_spec`, `forge_recreate_app`, `forge_generate_app`, `forge_verify_app`, `forge_rea_discover`, `forge_rea_tool`, `forge_wasp_cli`.

## 📋 Copy-and-Paste Example Prompts

### Example 1: Reference Website Recreation
> "Recreate https://example.com in ./output/example-app and verify fidelity."

**Expected Forge Workflow:**
1. Automatically identifies `https://example.com` as a web recreation target.
2. Launches headless Chromium, inspects DOM headings, paragraphs, and links.
3. Classifies target as `content` presentation (zero buttons, no forms).
4. Generates a clean full-stack application using `contentPageTemplate`.
5. Verifies server startup, `/api/health`, and database persistence.
6. Returns parity score (1.00) and run instructions.

### Example 2: Greenfield Application Generation
> "Build a student management app with attendance and fee tracking in ./output/student-app."

**Expected Forge Workflow:**
1. Classifies request as greenfield application generation.
2. Synthesizes `ForgeSpec` with `Student` and `Attendance` data models.
3. Generates the full-stack application using `studentManagementTemplate`.
4. Initializes SQLite tables with WAL mode and initial mock records.
5. Runs syntax validation and test suites.
6. Returns directory path and start commands (`node server.js`).

## ⚠️ Known Limitations & Troubleshooting

1. **Wasp Engine on Windows:** Full-stack Wasp generation requires Windows Subsystem for Linux (WSL) due to upstream Wasp CLI architecture. On native Windows, the Universal Node engine (`node:sqlite` WAL) is the active default.
2. **Offline Reference Websites:** If a reference URL is unreachable, Forge reports the target as inaccessible and falls back to user prompt context rather than claiming live browser inspection.
3. **npm Registry Status:** The package has been prepared and verified for publishing, but is not yet published to the public npm registry. Local installation from source or tarball is currently supported.
